Part 1 — Meet xAuby

1.1 What is xAuby

xAuby is an automated gold trading program. It runs around the clock on OKX without anyone needing to watch a screen. The bot continuously pulls in the latest gold price, analyzes it against the strategy it's configured with, and decides on its own whether to buy or sell — complete with risk protection and Telegram alerts so the owner can check in from anywhere, anytime.

The system can run several trading pairs at once (right now only one — gold — is actually turned on), and can be controlled through several channels: terminal commands, a terminal dashboard screen, and Telegram.

1.2 The Thinking Behind the Design

The principles the system has followed from the start, in plain terms:

  • Everything is configured through files, not code changes — want to change the trading pair, the strategy, or any setting? Edit a configuration file. You don't need to be a programmer.
  • Strategies plug in and out like modules — the core engine isn't tied to any one strategy. New strategies can be added without touching the rest of the system.
  • Configuration is split into three clear groups (details in Part 4) so that backtest results always match what happens in live trading.
  • Safe by default — the system always starts in simulation mode. Switching to real money requires setting several confirmations at once (see section 2.5), which prevents accidentally trading real funds.
  • Each trading pair is fully isolated — if several pairs are running, a problem with one won't affect another. The trading capital itself is intentionally shared across all pairs.
  • Features can be switched off instantly — every major feature can be turned back off with a single flip of a setting, no code changes or reinstalling required.

1.3 How the System Is Configured Right Now

PairModeStrategyMain chartConfirm chartSides allowed
XAUUSDTLivecdc_action_zone 4 hoursDailyLong + Short

The bot trades OKX Perpetual Swaps (contracts with no expiry date) at 1x leverage — meaning no borrowed money is added to the risk at all. It also checks the funding rate (the interest rate paid between long and short traders) to make sure it isn't abnormally high, and always keeps a safe distance from the liquidation price. Backtesting uses a gold-tracking token instead of the live gold contract, since it has a much longer price history that closely mirrors real gold.

The live strategy can open both long and short at once, in a stop-and-reverse style — in plain terms: if the bot is holding a long position and the signal flips to bearish, it closes the long and opens a short immediately, in the same beat, with no waiting.

How orders get sent: when entering a trade, the bot first places a limit order at a set price. If that order sits unfilled too long, the bot switches to a market order instead, so it doesn't miss the move. When exiting in an emergency (a sudden signal flip, or a forced close), the bot always uses a market order for speed. Otherwise it uses the set-price order.

The current gold strategy has no traditional stop-loss — every exit is driven purely by the signal changing, and position size is calculated as a fixed fraction of capital rather than based on stop distance. It also takes an early partial profit: once profit reaches 12%, the bot sells 50% of the position, then lets the rest ride on the normal exit signal.

An important safeguard: if a live trading pair has automatic strategy-switching turned on but hasn't been formally approved by the operator, the bot will automatically force that pair back into simulation mode — this keeps unapproved features from ever touching real money. And whenever the market is judged to be in a dangerous zone (like a panic sell-off), the bot won't open new trades, keeps existing protection in place, tightens its safety margins, and can force-close a position if the dangerous conditions drag on too long.

1.4 What This Bot Does and Doesn't Do

What it does

  • Analyzes trading signals from price charts, based on the configured settings
  • Opens and closes real positions on the exchange, or simulated ones for testing
  • Keeps basic risk protection active at all times
  • Logs every event so you can review it later on-screen, when troubleshooting, or via Telegram

What it doesn't do

  • It does not guarantee any profit
  • It does not manage funds sitting in any OKX wallet other than the one configured for trading
  • It does not automatically make a strategy written by someone else safe, unless the code-scanning feature is turned on (see Part 3)
  • It does not replace your own review of risk, leverage, fees, and the exchange's rules
Warnings for new users:
  1. Right now the system is configured for exactly one live market: gold (XAUUSDT) on OKX.
  2. You must get simulation mode working successfully before ever considering real money.
  3. Trading with real money requires three conditions set at the same time: a command-line flag, a confirmation environment variable, and that specific pair marked as live in its configuration.
  4. The bot only reads the account actually configured for trading on OKX — not every wallet in your OKX account. If the dashboard shows a balance of 0.00, check that your funds are sitting in the trading account, and that the API key has permission to read/trade that account.
  5. Never enable withdrawal permission on the API key. The bot only ever needs permission to read and to trade — it never needs to withdraw funds.
  6. Only run one instance of the bot per data folder. If you need multiple accounts, you must separate the data folders (see Part 10).

Part 3 — How the System Works Behind the Scenes

3.1 A Simple Overview of the Pieces

This part explains how the bot works under the hood — useful if you want a deeper understanding. If you just want to operate the bot, feel free to skip ahead to Part 4 (Configuration) and come back later.

xAuby splits its work across 5 cooperating pieces:

PieceWhat it's responsible for
Human control layerTerminal commands, the dashboard screen, and Telegram — where a person gives instructions
Core engineMakes the actual trading decisions, manages risk, and sends orders
Strategy layerCalculates trading signals and chart data
Data layerPulls prices from the exchange and stores data
Event loggingRecords everything that happens, for later review and for driving the screens

The rough flow: a person starts the bot → the bot loads its configured trading pairs → each pair is processed separately → (if enabled) a strategy is picked automatically based on market conditions → trading signals are calculated → risk conditions are checked → a real or simulated order is sent → everything gets logged to the database → the screens update with the latest result.

3.2 What Happens on Every Cycle

The bot works in cycles, called "ticks" (for example, checking in every 60 seconds). On every cycle, it goes through this sequence for each active trading pair:

Steps for each trading pair

  1. Pull the latest price candles from the exchange
  2. Check whether the fast price feed (WebSocket) is still fresh — if it's too stale, fall back to a backup price source instead
  3. Check whether a position is currently open
  4. Load the strategy and capital settings for that pair
  5. (If enabled) analyze market conditions and automatically pick the right strategy
  6. If market conditions are judged dangerous, skip opening new trades and tighten protection
  7. Otherwise, let the strategy calculate its trading signal as normal
  8. Check for abnormal news/market conditions before allowing any buy
  9. Act on the signal: open a new trade, close one, or hold while managing partial profit-taking and the trailing stop
  10. Log everything and update the screens

When opening a new trade

  1. Check whether today's trade count or loss limit has already been hit
  2. Check that the order size isn't too small, or the price too far from what was intended
  3. Calculate position size from the available capital and the configured risk percentage
  4. Send a real or simulated order, depending on that pair's mode
  5. Set risk protection (if that strategy uses one)
  6. Send a Telegram alert confirming the buy/sell went through

When closing a trade

Several things can trigger an exit: a sell signal from the strategy, an early partial profit-take hitting its target, a stop-loss that's been confirmed repeatedly, detecting that a stop order already filled on the exchange, a forced close after too long in a dangerous market condition, or a maximum holding time being reached. If a sell fails, the system tries to re-establish protection and sends a critical Telegram alert if that also fails.

Taking partial profit early

This feature only runs after the system has already confirmed there's no full-exit signal in the same cycle (a full exit always wins if both happen at once). Once the current price is better than the entry price by the configured percentage, the bot sells part of the position, resizes any protection to match what's left, and lets the remainder ride on the normal exit signal.

Safely handing off between strategies

Think of it like changing drivers mid-trip — if the system switches strategies while a position is open, the original strategy keeps managing that position until it closes. The new strategy won't touch it until there's nothing left open. This avoids confusion over who's responsible for which trade.

When the market is in a dangerous zone

Once market conditions are classified as dangerous, the bot will: block all new trades, keep the existing protection on any open position, tighten its safety margins, wait for conditions to normalize for a while before trading again, and can force-close a position if the dangerous conditions persist too long.

Short trading

Strategies that support short trades send separate "open short" / "close short" signals rather than reusing the normal buy/sell signals. The stop-loss for a short sits above the entry price (the mirror image of a long). The bot always double-checks its recorded position against the real position on the exchange, and will stop trading immediately if they don't match — this prevents the bot from getting confused about what it's actually holding.

3.3 How Multiple Trading Pairs Stay Separate

The system loads its list of trading pairs from a configuration file. If the "pair list is the single source of truth" setting is on, that file governs everything, and if "auto reload" is also on, the system checks that file periodically and picks up new pairs without needing a restart.

Each active trading pair keeps its own fully separate data, including:

  • Its latest price
  • The strategy currently in use (and a handoff target, if one is in progress)
  • Its latest market condition
  • Its mode — simulation or live
  • Any pending confirm-before-buy state
  • Its latest signal data, for the screens and Telegram

Trading pairs are isolated at the strategy and processing level, but the trading capital and overall risk conditions (like the daily maximum loss) are intentionally shared across all of them.

3.5 Strategies and Charts Must Travel Together

This is the most important rule for extending the system: every new strategy must ship with a matching chart display. Add a new strategy without a compatible chart, and the screen will show something that doesn't match what the strategy is actually doing — leaving the user with a wrong impression of what the bot is up to.

A strategy must be a "pure analyst" only — it must never send orders itself, touch the database, or call Telegram directly. Its only job is to analyze and hand back a signal. The core engine is the one that actually decides what to do with that signal.

Checklist for adding a new strategy (for developers)

  1. Write the new strategy and register it with the system
  2. Write a matching chart display (or reuse a compatible one)
  3. Add the strategy-to-chart mapping in the configuration file
  4. Write tests covering the strategy, its chart display, and the on-screen legend
Some strategies in the system are tagged "research only" — the system will automatically block that entire group from ever running on a live pair. They can only be used in simulation or backtesting.

4.2 Why Configuration Is Split Into Three Groups

All settings are divided into three clearly separated groups. Putting a value in the wrong group is the most common source of bugs, because backtesting and live trading must read values from the same place — get it wrong, and backtest results will stop matching live results.

GroupOwnsMust not own
Engine settings Exchange connection, logging, notifications, overall risk limits, feature switches Strategy signal/exit parameters
Strategy settings Indicator values, stop-loss, trailing, breakeven, timeframe, signal/exit logic Secrets or position sizing
Portfolio settings Position sizing, capital allocation Indicator/signal rules

The rule to remember: anything that can change a backtest result belongs in the strategy or portfolio group only — never in the engine group.

5.3 What Is the Market Regime Detector

The Market Regime Detector is the part of the system that keeps watch over what kind of market is currently in play — a strong uptrend, a strong downtrend, sideways chop, or a panic sell-off — and tags the current state with a label. That label helps decide how much risk to take, and (if enabled) can automatically pick the strategy best suited to that condition. It analyzes the market from four angles and produces one of 11 possible labels:

The four angles it analyzes

  • Trend direction — how short- and long-term moving averages line up, and how far the current price sits from the long-term average
  • Volatility — whether price is swinging more or less than usual, compared against its own behavior over the last 120 candles (relative, not a fixed number — which is exactly what makes it work across different assets and eras)
  • Liquidity — trading volume compared to its 20-candle average
  • Macro factors — combines the dollar index, interest rates, and news sentiment into one score, capping each input so no single one (say, a stray news score) can dominate the result

LabelMeaning

BULL_TREND_STRONGA strong uptrend with clear momentum
BULL_TREND_WEAKA weak uptrend, or macro factors conflicting with the trend
BEAR_BREAKDOWNA downside breakdown with expanding volatility
BEAR_TREND_STRONGA strong downtrend
BEAR_TREND_WEAKA weak downtrend
PANIC_SELLA panic sell-off — a sharp downtrend with a spike in volatility

VOLATILITY_EXPANSIONExpanding volatility with no clear direction
SIDEWAYS_CHOPDoesn't fit any other condition — directionless chop

Confidence score

Every label comes with a confidence score, from 5% to 98%. The higher the score, the more confident the system is that the label is correct. It's calculated from several combined factors (trend clarity, how well macro factors align, how clear the volatility reading is, and more) — not a simple yes/no like a basic system would give.

Protecting against bad calls from too little data

The regime detector needs at least 200 candles of price history to calculate a reliable long-term average. If it's given less than that, it won't dare call the market bullish or bearish — it labels the condition "not yet clear" instead and lowers its confidence score. This protects against a wrong call made from insufficient data.

5.4 A Statistical Second Opinion

Beyond the main rule-based detector — whose thresholds were set by hand by a person — the system also runs a second checker in parallel that uses pure statistics instead of fixed rules, acting as a "second opinion" that carries no bias from anyone's pre-set thresholds.

  • It lets the computer try grouping price data on its own, based purely on recent price direction and volatility, without using any fixed rule at all (this method is called a Gaussian Mixture Model, or GMM)
  • It only looks at these two things (direction and volatility) because real data proved the system separates volatility far more clearly than direction
  • The result is whichever group the latest candle is closest to, along with a confidence level and how long that group has historically tended to last

This result is purely supporting information — it never changes the main regime label or the strategy selection. It's off by default; you have to turn it on yourself if you want to see this extra data.

5.5 How Accurate Is the Regime Detector, Really

A lot of people ask "how accurate is this thing, really?" The answer isn't a percentage-correct score like a school test, because nobody actually knows the "correct" answer for what the market was doing at any given moment. A more meaningful way to measure it is to look at three things instead:

  1. Does it actually separate volatility? — when the system says the market is in one condition, is the price actually more or less volatile than in a different condition? (This is the main job, since it drives how much risk to take.)
  2. Does a label last long enough to matter? — if the label changed on every single candle, it would be useless for decision-making.
  3. How accurate is it at predicting direction? — this is a bonus, not the main measure. It's normal and expected for this to be weak in any market-analysis system.

We tested this using several years of real gold and Bitcoin price history, measuring how clearly the labels separated actual volatility, and how likely that result was to be pure chance.

What was measuredGoldBitcoin (comparison test)

The takeaway: the regime detector does its main job well — it genuinely and reliably separates volatility (not by chance), labels stick around long enough to actually be useful (roughly 5-7 candles on average), and uptrends really do outperform downtrends as expected. Predicting the very next move is weak, which is normal for every market-analysis system out there. The practical conclusion: use the regime label to decide how much risk to take, not to predict whether price goes up or down next.

The statistical second opinion agrees with the main detector only about half the time, and that's by design. If the two agreed almost 100% of the time, having a second checker wouldn't add anything. When they disagree, that's a sign the market is genuinely hard to read at that moment — useful information, not a bug in either system.

Limitations worth knowing

  • The volatility-separation result is small in absolute terms — most of the market is just noise, and no market-analysis system explains a huge share of it. "Very high confidence" means the separation is real and reliable, not that it's huge.
  • The gold price history used for testing comes from a tracking token, since the live gold contract itself has a shorter history.
  • The thresholds are still set by hand — they haven't been automatically tuned per asset yet. The statistical second opinion is a first step toward a more data-driven system in the future.
  • The return figures measured are descriptive statistics, not a backtest proving any particular strategy is profitable.

5.6 Automatically Picking a Strategy for the Market

This feature maps each market condition to the strategy best suited for it. It's opt-in per trading pair, not turned on automatically:

  1. The system-wide master switch must be on
  2. The switch for that specific pair must also be on
  3. If it's a live pair, it also needs explicit operator approval

If a live pair enables this without approval, the bot automatically forces it back to simulation mode. Other behavior: it waits for the market-condition signal to repeat for 3 candles before confirming a real change (to avoid false signals); during a dangerous condition it blocks new trades but keeps existing protection in place; and it requires a stretch of normal, tradeable candles before returning to full trading — with a safe strategy handoff as described in section 3.2.

5.7 How Strategy Changes Get Decided With Real Data

The system has a review process before ever swapping out the strategy assigned to a given market condition — a challenger strategy can only replace the current one if it proves it makes more profit across both the data used to tune it and fresh data it has never seen, with enough trades and losses staying within an acceptable range. The data makes the decision, not a gut feeling.

Latest test result: testing against over 26,000 candles of Bitcoin history, no challenger strategy passed every requirement, so the existing strategy stays in place for every market condition. This test was run on Bitcoin, which isn't currently a live trading pair — it serves as an example of the process for deciding on future strategy changes.
Part 6 — Risk Management

6.1 How the Bot Sizes a Position

Every position size is calculated from two things: the total portfolio value right now, and the risk percentage that's configured. In plain terms: as the portfolio grows from profits, the next trade's size automatically grows along with it (compounding) — always capped by a maximum, so no single trade can ever get too large.

Important: the risk percentage must be set consistently everywhere in the configuration file, because live trading and backtesting read it from different spots. If they don't match, backtest results stop reflecting live results. The system currently uses 2% everywhere. There's also a startup check that immediately rejects any risk setting above 10%, since that would be dangerously high.

6.2 Stop-Loss, Trailing, and Breakeven

Risk-protection mechanisms the system supports (not every strategy uses all of them — see the actual CDC settings in section 5.2):

  • Initial stop-loss — sets a distance from the entry price based on market volatility
  • Trailing stop — as price moves favorably, the protection level moves along with it to lock in some profit
  • Breakeven — once profit hits a set threshold, the stop moves to the entry price exactly, so that trade can no longer lose money (if this is enabled)
  • Multi-check confirmation — for strategies with no stop-loss directly on the exchange, the signal must repeat across several checks before the bot actually closes the trade, to avoid a false signal from a brief price spike

6.3 Taking Partial Profit Early

Configurable in the strategy settings:

strategy:
  params:
    cdc_action_zone:
      partial_tp_pct: 12.0
      partial_tp_fraction: 0.5

Once an open position's profit reaches the configured percentage from entry, the bot immediately sells the configured fraction, records it as a partial close, then lets the remainder ride on the normal exit signal. This only fires once per trade, and it remembers that it already fired even across a bot restart. For the current gold setup, that means banking 50% profit at +12%, then letting the rest ride until the signal changes. The screen shows this as "pending" or "profit already taken."

6.4 The Portfolio-Wide Loss Switch

The system has a portfolio-wide emergency switch: if the total portfolio value drops below a set percentage from its highest point ever recorded, the bot immediately blocks new trades (and can be set to force-close open positions too). Think of it as an emergency brake against compounding losses during a prolonged bad stretch.

6.5 Short Trading and Its Safety Conditions

The current pair can genuinely open short positions with real money, because the connected exchange supports everything that's required. Safety conditions for short trading:

  • Must be explicitly allowed for that specific pair in the configuration
  • Going live requires an extra switch to be turned on — otherwise it's paper-trading only
  • If the connected exchange doesn't support everything required, the system refuses to start at all (choosing safety whenever it isn't sure)
  • Leverage defaults to 1x, capped at a maximum of 3x
  • If the real-time price feed runs into trouble, the system immediately blocks any new short trades

Part 7 — Backtesting and Research

7.1 Where Backtest Data Comes From

Backtesting pulls price data from the global Binance exchange by default, since it has a much longer price history to test against. Live trading uses the actual configured OKX data. Both backtesting and live trading read their settings from the exact same place, so results from both stay consistent with each other.

7.2 Backtest Commands

python scripts/replay_backtest.py --symbol XAUUSDT --config bot_config.yaml
python scripts/optimize_pair_configs.py

Trying out a new strategy is always a dry run by default — it never overwrites real settings immediately:

python scripts/select_pair_strategy.py --symbol BTCUSDT --candidates a,b,c
python scripts/select_pair_strategy.py --symbol BTCUSDT --candidates a,b,c --apply

Only adding --apply will actually write a passing winner back into the real configuration.

7.3 Regime-Aware Replay

This feature can be turned on per pair in the strategy settings — once enabled, the regime detector runs inside the backtest itself. Buy signals get suppressed whenever the market condition at that moment doesn't match the strategy's target conditions, which makes backtest results closer to what actually happens during live trading.

7.4 Validating Correctness After a Restart

Always run this after a restart, after any incident, or after changing important settings:

python scripts/replay_validate.py <run_id> --symbol XAUUSDT

This checks whether the signals the bot recorded during live trading match what the same strategy would calculate in a backtest — a fast way to catch anything unusual.

8.3 Design Philosophy

The WebUI is designed to feel like a "private gold desk" for a single owner, checked quickly from a phone or computer — not something you sit down and work in. The one question it must answer within 10 seconds: "Is the bot still running, what's my balance, what position am I holding, has anything happened?"

Design principles

  • Glanceable first — balance → current position → signal → everything else, no scrolling needed to see what matters
  • Color only ever means one thing — green/red/amber always mean profit/loss/warning and nothing else; the brand's gold accent is used only for identity, never for status
  • Read-only means calm — nothing on screen implies you can control anything from here. Anything abnormal stands out clearly; normal operation stays quiet
  • Mobile-first design — tap targets sized for fingers; the desktop version gets the same layout centered on the page, not a different one

Part 10 — Multiple Accounts and Exchanges

10.1 Running Several Bots on One Machine

xAuby separates its configuration from the data it generates while running, which lets you run several bots (different accounts, exchanges, or sets of pairs) side by side on one machine without them colliding — just point each one at its own separate data folder.

XAUBY_CONFIG_DIR=instances/acct1 XAUBY_INSTANCE_ID=acct1 \
  python run_xauby.py --live

Each instance reads its own .env file, so secrets never need to be shared across accounts.

10.2 Switching to a Different Exchange

You can switch exchanges entirely through the launcher menu, no manual file editing needed — a wizard walks you through picking the exchange, entering your connection details, testing the connection, and offers to restart afterward:

exchange:
  provider: ccxt
  ccxt_id: kraken
  api_key_env: KRAKEN_API_KEY
  api_secret_env: KRAKEN_API_SECRET
  quote_asset: USDT

The system supports adding brand-new exchanges without touching the core code — a developer just needs to add one new connector file, and the system discovers and uses it automatically.

10.3 OKX Perpetuals and Short-Trading Safety

The certified derivatives path uses isolated-margin perpetual swap contracts. The system refuses to start immediately if the selected exchange doesn't support everything required for short trading (choosing safety whenever it isn't sure), and if the real-time price feed runs into trouble, it immediately blocks any new short trades.
