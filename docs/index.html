xAuby operator security baseline

A compact security landing page for the current xAuby hardening work: WebUI access control, runtime path isolation, secret scanning, and the remaining production SaaS gaps.

Current posture: safe for localhost, SSH tunnel, or authenticated Tailscale access. Public SaaS exposure still requires a reverse proxy, tenant identity, RBAC, and secret-manager backed credentials.

Open Audit WebUI Setup

WebUI Boundary

Non-loopback binds now require Basic Auth or a bearer token. Responses include security headers and redact secret-like JSON keys.

Tenant Paths

Runtime instance IDs are validated as slugs to prevent path traversal when running multiple engines on one host.

Secret Hygiene

A dependency-free repository scanner checks tracked files and git history for credential-shaped values before release.

Release Gate

Before publishing a VPS or SaaS build, run the same local checks used in CI.

  • python scripts/scan_secrets.py --tracked --history
  • python -m pytest tests/test_webui.py tests/test_runtime_paths.py
  • Set XAUBY_WEBUI_PASSWORD for Tailscale IP binds
  • Keep XAUBY_WEBUI_ALLOW_UNAUTH_REMOTE unset in production
xAuby is still a single-operator trading runtime. Treat this page as an operational security baseline, not a complete SaaS security boundary.
